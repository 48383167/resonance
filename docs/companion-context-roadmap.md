# 情感陪伴与私密内容融合路线图

## 结论

不应把日记、情书、瞬间等私密内容直接用于“训练模型”。对单个用户而言，最有效、也最可撤回的方案是**用户明确选择内容后的上下文引用（RAG）与可编辑记忆**：在一次咨询中临时把少量获准内容作为参考发给模型，而不是把内容写入模型参数。

这样能让助手更懂当下的关系背景，同时保留删除、撤回授权和数据最小化的能力。V1 已维持“绝不自动读取业务内容”的规则；以下是后续新增能力的规划，并非已启用行为。

## 不变规则

- 情感助手始终是用户私有空间；不会把对话或引用内容展示给伴侣。
- 日记、情书、瞬间、照片等内容默认不进入模型，也不进入检索索引。
- 每一次向第三方发送内容都需在界面中说明“哪些内容会被发送给 DeepSeek、用于什么目的”。
- 发送给第三方后的内容无法靠删除本地记录撤回；撤回授权只影响后续处理。
- 不读取未解锁时间胶囊；V1 不发送图片、音视频或其自动识别文本。
- 情绪危机识别优先于任何上下文检索，仍只使用本地安全回复。

## 三阶段实现

### 第一阶段：逐项引用（优先实施）

在日记、情书和瞬间详情页增加“和心语聊聊这条内容”入口。用户点击后，在确认页选择要引用的片段并确认发送；助手对话中只显示来源卡片（类型、标题、日期），不自动长期保存原文副本。

授权规则：

- 仅自己可见的日记：作者本人可逐项授权。
- 双人共享内容：请求者同意还不够；若文本由伴侣创作，作者也必须在该条内容上允许“用于情感助手第三方处理”。
- 已撤销、已删除、无权查看、或未解锁的内容，在发送时再次校验并拒绝使用。

每次调用最多选 3 项、总文本设置严格上限；由服务端读取最新正文、清除不必要的元数据后临时拼接给模型。只记录来源 ID、版本/哈希、授权版本、处理时间与供应商，不复制保存引用正文。

### 第二阶段：可编辑的“我的相处偏好”

助手可以在对话结束时提出一条候选记忆，例如“冲突时希望先被倾听，再讨论解决方案”。用户主动确认后才保存到自己的记忆列表；可查看、编辑、暂停和删除。模型只获得这些短小、已确认的偏好，不从日记自动推断并永久保存。

这比模型训练更适合个性化：修改立即生效，删除也能立即停止后续使用。

### 第三阶段：授权范围内的语义检索

当逐项引用和权限模型稳定后，再为用户主动启用的内容建立检索索引。每次咨询只检索少量相关片段，并在回复旁显示“本次参考了哪些内容”，让用户能移除某项。索引与原文按用户/情侣/作者授权范围隔离；内容更新、删除或撤回授权时必须同步删除索引。

向量化本身也可能属于第三方数据处理：若使用外部嵌入服务，必须单独征得同意；优先评估本地嵌入以减少外发。无论采用哪种适配器，检索模块对情感助手只暴露一个小接口：给定当前用户、已选内容和问题，返回已授权且经过长度限制的参考片段；权限判断、撤回、审计、去重和提示注入隔离都封装在模块内部。

## 为什么不做原始内容微调

微调会把难以删除的私密语料交给模型训练链路，成本高、效果难以验证，也无法及时反映新的日记或撤回授权。它还会把伴侣共同内容的同意、数据保留和供应商使用范围变成更高风险的问题。

如果未来确有产品级训练需求，只能考虑完全独立的、去标识化且自愿参与的数据计划：单独的明确授权、目的与保留期限、退出机制、供应商合同与安全评估、质量/偏差评测，以及不参与不影响现有功能。它不应使用任何默认的私密日记、情书或聊天记录。

## 交付顺序与验收

1. 先完成第一阶段的接口契约、双人授权表、来源选择 UI 与审计记录；测试作者/伴侣/撤回/删除/时间胶囊隔离。
2. 再上线可编辑记忆，支持一键清空与导出/删除验证。
3. 最后以小范围自愿试用验证检索质量、隐私提示和成本，再决定是否扩大范围。

每阶段均要求：无授权内容不得离开服务端；模型提示不得把引用内容当作指令；助手不得代替用户发送、修改或公开平台内容。
