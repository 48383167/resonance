# 需求提法模板

给 architect 提需求时，把「目标 / 约束 / 验收」三要素说清楚，architect 就能自主拆解、
委派 backend-dev / ui-dev 并闭环验收。简单单端小任务只需一句话目标即可。

## 模板骨架

```
帮我做 [具体目标]。

约束：
- 严格遵循 AGENTS.md 与 docs/Resonance_Architecture_Refactor_Plan.md
- 渐进式，不推倒现有代码；对外 API 路径 / 响应保持兼容
- 涉及前后端联动时，先出 API Contract 存到 docs/api/ 再动手

验收：
- 跑通 scripts/smoke.mjs（全绿）
- 更新 docs/api/refactor-progress.md（若是重构任务）
- 完成后说明：改了哪些文件、新增/变更 API、是否涉及数据库
```

## 场景示例

### 1. 架构重构（Phase / 模块迁移）

```
开始架构重构 Phase 1：搭建 server/src 骨架。
按重构计划 §22 执行，只创建 config/common/middleware/modules/infrastructure 目录，
不改动现有 routes 和 API，旧服务必须继续正常运行。
完成后更新 docs/api/refactor-progress.md 勾选 Phase 1，并跑 smoke 确认没破坏现有功能。
```

```
迁移 auth 模块到 modules/auth（routes/controller/service/repository/schema）。
保持 /api/auth 路径和 {ok,data}/{ok,error:{code,message}} 契约不变，
按重构计划 §5-§13 分层。完成后跑 smoke 验收并更新进度文件。
```

### 2. 前后端联动新功能

```
新增「恋爱纪念日倒数」功能：首页显示最近纪念日倒计时。
前端后端都做。先定 API Contract 存到 docs/api/，再分别委派 ui-dev 和 backend-dev 实现，
最后对照契约检查字段一致。
```

### 3. 单端小任务

```
给日记接口加一个 weatherCode 字段，只改后端，保持契约兼容。
```

## 提示

- 明确「单端还是双端」，architect 才知道要不要同时调 ui-dev 和 backend-dev。
- 重构类任务务必写「API 保持不变」，否则可能顺手改接口。
- 明确「跑 smoke + 更新进度文件」，architect 才会闭环验收。
